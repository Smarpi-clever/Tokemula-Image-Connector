# Tokemula 图片

使用已连接的 `tokemula-image` MCP 工具完成图片任务。提交按用户授权执行，沿用客户端的信任与审批；凭据和 HTTP 由 Connector 管理，不读取 Key、拼接请求或修改允许规则。

## 选择能力与执行方式

普通图片请求省略 `model`，由 Connector 使用用户设置的默认模型和有序备用。用户明确指定模型时原样传递；不猜型号、不自行补模型或重做降级链。需要查看模型能力时用 `list_image_models`。

用户只描述图片时，省略 `size` 和 `quality`，由 Connector 应用已保存的对应操作/模式偏好；尚未设置则使用模型默认。用户本次明确指定尺寸或画质时传入对应参数，覆盖已存偏好。像素尺寸按当前模型能力选择，自定义宽高遵守目录规则；批量的 `1K/2K/4K` 是分辨率等级，保留原值。

图片思考复杂度使用 `complexity`，与画质和 Harness 语言模型的推理强度分开。常规请求省略该字段，由 Connector 在支持的路径明确发送 `medium`；用户单次要求时可传 `low/medium/high`。路径不支持显式参数时，先报告并请用户调整，不删参数或换一组较低要求提交。

尚未连接或用户需要更新设置时，用 `configure_tokemula` 取得本机连接页或终端命令。API Key 只由用户在本机页面或自己的隐藏输入终端填写，不接收聊天中的 Key。自动降级仅发生在提交前，结果未知时沿原引用恢复。

- 文生图用 `generate_image`，已有图片编辑用 `edit_image`。默认同步；需要先取得任务引用、稍后取图时显式选 `single_async`。
- 编辑使用用户提供或本会话前次图片工具返回的本地绝对路径。“编辑刚才那张”直接使用对应原图路径，不再要求上传或去 Finder 复制路径。单图沿用 `image_path`；多图使用 `image_paths` 并保留顺序，两者二选一。mask 作用于第一张输入图，格式、透明通道和尺寸关系按所选能力检查。
- 多参考图、mask、背景、输出格式、压缩和输入保真度只在当前目录支持时使用；未要求的高级选项保持省略，不裁剪、重绘或丢弃输入图来绕过限制。
- 多条独立图片任务用 `submit_image_batch`。整个批次共用一个模型；每项使用稳定 `custom_id`，保持参考图顺序。单次请求的 `n > 1` 仍是普通生成或编辑，不自动改成批量。

## 沿原引用恢复

提交结果未知时保留返回的引用，不重新生成：

- 有 `task_id`：用 `get_image_task` 查询单异步任务。
- 有 `request_ref`：保留该请求引用，供站内记录核对；只有请求引用时不推断图片结果，也不重新提交。
- 有 `batch_id`：用 `get_image_batch` 查询批量状态和条目，再用返回的真实 `custom_id` 取得指定图片。分页使用返回的 `next_cursor`，每次按需读一页，不把第一页当成全部结果。
- 批量提交只有幂等键、尚无 ID 时，可读取任务列表，由调用方确认目标。仅在明确要求重放原提交时，使用同一幂等键和相同输入；冲突时保留原键，不换键重试。

处理中返回当前状态和引用，后续按需查询。停止等待与业务取消分开：单异步不支持业务取消；批量取消用 `cancel_image_task`，以返回状态为准，仍在运行时说明取消尚未完成。已完成部分可能计费，失败或取消状态不推导退款。

## 交付图片

展示已取得的图片，保留返回的模型、状态和任务引用。费用统一在 [Tokemula 网站](https://tokemula.com)查看；用户询问价格或消费时引导网站，不调用费用接口或在对话中估算、展示金额。

macOS 产品默认把本次完整原图保存在当前用户桌面的 `Tokemula-Images` 文件夹。以结果 `local_files` 的真实绝对路径为准，按 `image_index` 保序；`persistent=true`、`retention=user_managed`、`expires_at=null` 表示用户产物无自动过期。编辑输出另存，不覆盖原图。不要把旧图、缩略图或内存资源当作这次原图。

**WorkBuddy：取得本次路径后立即执行原生展示，再回复用户。**

1. 从当前宿主的已发现工具中查找原生 `present_files`；需要时使用宿主的工具发现入口，不猜命名空间，也不把 MCP `generate_image` 的成功当作展示成功。
2. 调用 `present_files`，`files` 仅包含本次 `local_files` 的完整原图绝对路径，第一项为应先显示的图；`cwd` 使用当前任务工作目录，不用图片输出目录代替。这里传原始绝对路径，不传 URI；展示已有文件不再复制到临时目录。本地图片由返回的 `files` 和 `focusFile` 打开；`previewed` 只列网页 URL，`previewed=[]` 不表示本地图片展示失败，成功时不用向用户播报这些内部字段。
3. 最终回复在正文嵌入本次原图：`![本次原图](local-file://local/编码后的绝对路径)`，同时留下同一原文件的可回看入口。图片语法直接写在正文，不放代码块、不转义，也不只给链接或文字说明。只有原生展示完成后才说已展示；失败时简短说明实际路径和状态，不建议重新生成。

正文 URI 使用 WorkBuddy 已有的 `local-file://local/` 格式：将真实绝对路径的反斜线统一为 `/`，按 `/` 分段，对每个非空段分别执行 `encodeURIComponent`，保留分隔斜线并去掉开头的多余斜线，再加上述前缀。中文和空格必须编码，不把分隔 `/` 编成 `%2F`。例如原路径 `/Users/a/Desktop/Tokemula-Images/中文 空格.png` 对应 `local-file://local/Users/a/Desktop/Tokemula-Images/%E4%B8%AD%E6%96%87%20%E7%A9%BA%E6%A0%BC.png`。`file:///` 不用作正文图片目的地址；它仍可用于已经验证的原生文件链接。原生 URI 仅用于 WorkBuddy 正文展示，`present_files.files`、`edit_image.image_path/image_paths` 始终使用真实文件路径。

**Codex：** 沿用宿主已有的图片显示方式，并保留本次原图绝对路径；需要在回复中嵌图时使用绝对路径的 Markdown 图片。其他客户端沿其实际展示能力交付，不强迫调用 WorkBuddy 工具。

旧聊天回看仍使用同一文件。再次展示或重新打开历史路径（不是本轮刚写完的输出）前，先用宿主只读文件检查确认它仍存在且可读；`present_files` 返回路径不作为文件存在性证明，图片加载后的 alt 文本也不当作图片。文件被用户移动或删除时，明确说明原路径已失效；不可读时如实说明读取错误。此时停止展示，不生成或编辑、不猜新位置、不换旧图；需要继续时再请用户给出实际新位置。Key、模型和图片默认设置继续由 Connector 管理。

已有真实路径时直接展示和继续编辑，不回退到索取路径或上传。旧版本/非 macOS 结果只有内联图、没有可用原图路径时，先用宿主正常保存或附件入口；仍取不到才请用户保存并上传。不要从会话数据库、内部日志或进程缓存提取媒体，不做全盘扫描，不重新生成。

旧兼容结果若明确返回临时预览和到期路径，按其返回期限说明；桌面持久产物没有 10 分钟或 24 小时到期，不从远端期限推导本地期限。

## 使用示例

- “用 Tokemula 生成一张极简风格的咖啡店海报。”
- “按这两张图的顺序编辑，用这张 mask 修改第一张图的背景，保留主体。”
- “把这三条商品图片需求提交为一个批次；稍后按批次 ID 查结果。”
- “刚才的任务没有返回图片，用这个任务 ID 继续查询，不要重新生成。”
